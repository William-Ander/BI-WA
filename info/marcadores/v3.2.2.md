# v3.2.2 - Etapa 3: Performance e tempo real

Data: 2026-05-29

## Objetivo
Melhorar a performance dos dashboards e tornar a atualização em tempo real mais inteligente, reduzindo carga desnecessária no MySQL e no navegador.

## Melhorias aplicadas
- Cache de consultas SQL de leitura com TTL configurável.
- Deduplicação de consultas simultâneas iguais: se dois visuais pedirem a mesma consulta ao mesmo tempo, o servidor executa uma vez e compartilha o resultado.
- Atualização por relatório no Socket.IO, respeitando o `refreshSeconds` individual de cada relatório.
- Pausa real da assinatura Socket.IO quando o dashboard é pausado ou quando a aba fica oculta.
- Reassinatura automática quando a aba volta a ficar visível.
- Status de cache/tempo real exibido na barra do dashboard.
- Botão de limpeza de cache disponível no Desktop/Admin.
- Invalidação automática do cache após alterações em relatórios, transformações, estrutura e tabelas manuais.
- Endpoint `/api/realtime/status` para diagnóstico de cache e modo de atualização.
- Endpoint `/api/realtime/cache/clear` para limpar cache no Desktop/Admin.
- Base opcional de invalidação por evento no MySQL usando tabela de controle.

## Variáveis novas
- `BIWA_QUERY_CACHE_ENABLED=true|false`
- `BIWA_QUERY_CACHE_TTL_MS=15000`
- `BIWA_QUERY_CACHE_MAX_ITEMS=250`
- `BIWA_REALTIME_EVENT_TABLE=`
- `BIWA_REALTIME_EVENT_COLUMN=updated_at`
- `BIWA_REALTIME_EVENT_POLL_SECONDS=5`

## Observação
A atualização continua compatível com o modo atual por intervalo. Para um comportamento mais próximo de evento real, configure uma tabela de controle no MySQL e informe `BIWA_REALTIME_EVENT_TABLE`.
